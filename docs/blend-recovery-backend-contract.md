# Controlled Blend recovery backend contract

Implemented in `0.2.33-blend.3`. See `blend-core-recovery-verification.md` for executed artifact-level tests and deployment status.

- QtRO slots `QVariantMap startBlendRecovery()`, `pauseBlendRecovery()`, `resumeBlendRecovery()`; replies `{ok,error,message}`.
- `PROP(bool blendRecoveryActive=false READONLY)` remains true for every unfinished flow including pause/attention/journal failures.
- `getBlendLifecycle()` always contains `recovery: {active,phase,title,detail,tone,steps,canStart,canPause,canResume}`. Base lifecycle health remains independent and truthful. Getters never send mutation requests.
- Journal: private (`0600`) `blend-recovery.json` beside `userConfig`, envelope `{version:1,scope:<absolute config path>,state:{...},checksum:<SHA256 compact state>}`. Lifetime `QLockFile` on `blend-recovery.json.lock`; atomic writes and directory sync on Unix. Corruption/unsupported version/scope mismatch/lock/write failure blocks mutations. Externally altered/deleted evidence is not silently overwritten or recreated.
- Header-only production controller `src/BlendRecovery.h`, strict canonical parser `src/BlendRecoverySnapshot.h`; standalone tests drive EXACT state machine with transport callbacks and real synthetic /extra journals.
- Flow phases: `idle`, `preflight`, `withdraw-ready`, `withdraw-pending`, `withdraw-wait`, `removal-wait`, `declare-pending`, `binding`, `activation`, `monitoring`, `complete`, `attention`. UI pause overlays the persisted underlying stage; no cancel.
- Start eligibility requires owned configured/runtime-verified canonical declaration, epoch >= active+2, valid single canonical locator+collateral, no scheduled/pending mutation. Reading never arms recovery.
- Requests: `/sdp/set-declaration-id` (JSON string), `/sdp/withdrawal` (JSON string), `/blend/join` (`{locator,locked_note_id}`). Withdraw/join journal BEFORE POST; ambiguous outcomes stay pending forever without automatic resubmission, including restart. A same-ID fresh declaration is accepted only with strictly newer `created` plus unchanged provider/collateral/locator.
- Funding HTTP read: `/wallet/<public-key>/balance` with pinned `{address,tip,balance,notes:{noteId:value}}`; require the requested address and current observed tip. Only the actual SDP funding key's positive non-collateral notes satisfy the fee prerequisite; primary balance is not substituted. Original collateral must appear in a known wallet, and join additionally waits for observed withdrawal, canonical absence and the LIB barrier. Wallet balances include locked notes: the internal `noteSpendable` flag is only original-note presence, NOT exact spendability proof, and positive non-collateral value does not prove fee sufficiency or an unlocked fee note. Node rejection/unknown-outcome handling remains authoritative. No faucet, regeneration, or auto node restart.
- Recovery snapshots are reset on every lifecycle call, including offline/failed/nested reads. Eligibility uses the strict canonical parser, integral bounded epoch/slot/LIB, a valid tip and runtime identity, Online and Core telemetry. `recovery.snapshot` exposes these observations and canonical record/provider/withdrawal fields; original journal fields are exposed separately, including offline. Legacy `submissionPending` is not used as recovery pending evidence: a stored confirmed ID is history, not an unresolved transaction.
- Native guards block manual declaration/withdrawal/binding, live-node restart/stop/force-stop, chain reset, config generation, key replacement and arbitrary-path keystore export for unfinished recovery (pause and faults included), before any process/node call. Explicit Start is allowed for `NotStarted`/`Stopped` only with the same config scope and public provider and no active recovery tick; it never automatically restarts a node. The actual generation/replacement entry points are `generateConfig` and `regenerateNodeKeys`. This does not guard unrelated module RPC interfaces outside this plugin.
- Scope changes call `Controller::fail()` against the original controller/journal. Attention state is persisted when storage is still intact, so reopening the old scope cannot revive an armed plan after an identity/config fault. Pause remains available over a reachable backend even if chain telemetry fails; Start/Resume still require reconciliation.
- Pinned registry GET has NO tip/lib argument. Recovery requires repeated canonical absence after observed effective withdrawal epoch, plus `cryptarchia_info.lib_slot >= first-absence observation slot`. Null/non-object/malformed registry never means absence. Slot barrier is a conservative finality wait, not an atomic historical registry proof.
- Completion requires observing three consecutive distinct accepted `active` epochs beyond `created+2`, runtime Core, AND current-run binding acknowledgement, not baseline/nonce/POST acknowledgement alone. Elapsed epochs alone cannot mark Core activation complete. The binding setter is repeated only when current-run acknowledgement is unknown, not on every monitoring poll. First three distinguishable renewal epochs (`created+3,+4,+5`) retain accepted/missed/unobserved coverage; a known miss is never relabelled unobserved. Completion makes no future-Core or payout guarantee.
